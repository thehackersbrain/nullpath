Kerberoasting

intermediate credential access T1558.003 requires: domain user updated 04 Sep 2026 · 7 min

Any authenticated domain user can request a service ticket for any account with a registered SPN. The ticket is encrypted with the service account's password hash, so the request itself hands you an offline cracking target — no privileged access, no touching the target host.

Tip

Service accounts with old passwords and RC4-enabled tickets crack fastest. Sort your roast output by encryption type before you feed hashcat — the $krb5tgs$23$ entries are the ones worth your GPU time.

How it works

When a user wants to reach a service, they ask the KDC for a TGS ticket for that service's SPN. The KDC returns a ticket encrypted with the NTLM hash of the account that owns the SPN. Because any domain user can make this request for any SPN, and the returned blob is crackable offline, the entire attack reduces to: enumerate SPNs, request tickets, crack.

Enumerate roastable accounts

Find every user account that has a servicePrincipalName set. These are the only roastable targets.

impacket · GetUserSPNs.py {{ copy1Label }} 
# list SPNs across the domain
GetUserSPNs.py -dc-ip 10.10.10.5 corp.local/jdoe:'Passw0rd!'

# request and dump crackable hashes in one shot
GetUserSPNs.py -request -dc-ip 10.10.10.5 \
  corp.local/jdoe:'Passw0rd!' -outputfile roast.txt
Warn

A single account requesting a large batch of TGS tickets is the signature blue teams hunt for. Space requests out, or target only the two or three accounts you actually intend to crack.

Crack offline

hashcat · mode 13100 {{ copy2Label }} 
hashcat -m 13100 -a 0 roast.txt rockyou.txt \
  -r rules/best64.rule -O

Detection footprint

  • Event 4769 (TGS request) with ticket encryption type 0x17 (RC4) — the highest-signal indicator.
  • A single principal requesting many distinct SPNs in a short window.
  • Honeypot SPN accounts: any request for them is malicious by definition.
